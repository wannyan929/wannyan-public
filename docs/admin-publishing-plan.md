# 管理室の安全な公開機能・設計メモ

## 現状
- サイト: GitHub Pages（静的ファイル、公開リポジトリ）
- 管理室: `admin.html`（公開ページ、端末内の下書き保存・プレビューのみ）
- 公開: GitHub Actions の手動フォーム（GitHubで書き込み権限が必要）
- 写真: 現在は別途 GitHub に登録。ブラウザ内プレビューのみ。
- GitHub API の認証情報や個人のアクセストークンは公開サイトに埋め込まない。

## 目標
- りょう・朱里がスマホでログインし、文章と写真を編集し、確認後に公開
- まるちゃんは接続済み GitHub 経由で編集を継続
- 公開サイトのトップページ、扉の演出、効果音、公式画像を変更しない
- GitHub Pages の静的配信を維持し、ページ閲覧時の負荷を増やさない

## 安全性の前提
- 静的 HTML/JavaScript だけでは、編集権限を安全に秘匿できない。
- Decap CMS を使用する場合も GitHub OAuth を仲介する安全な認証バックエンドが必要。
- 公開サイトに GitHub token、OAuth client secret、管理用パスワードを置かない。
- 管理者の認可はサーバー側で確認する。GitHub リポジトリへの書き込み権限も最小限にする。
- 朱里さんは GitHub アカウントの作成に同意済み。ユーザー本人がアカウントを作成した後、リポジトリ管理者が必要最小限の権限で招待する。招待・権限付与は未実施。
- サーバー側で写真の形式・サイズを制限し、公開前に内容を確認する。

## 実装順
1. GitHub アカウント方式で進める。OAuth 仲介の安全な実装と無料枠の条件を確認し、必要なアカウントを準備する。
2. 非公開の検証環境でログイン・編集権限を確認する。
3. 活動報告と任務予定の編集、写真アップロードを実装する。
4. 実際の更新テストを行ってから、既存の管理室から案内する。
5. 従来の GitHub Actions による公開方法を緊急時の予備手段として残す。

現時点では新しいワンタッチ公開機能は未実装。管理画面に「公開できる」と誤表示しない。
